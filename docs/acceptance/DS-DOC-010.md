## 0. Independent Acceptance Author Statement & Review Framing

### 0.1 Process Discipline & Task Boundary
DS-DOC-008 established the reflowed single-column reading surface (`ReflowBilingualReader.tsx`), unrolling prose into one column while carrying figures, tables, and formulas as pixel crops of the page. DS-DOC-009 refined typography, magnified vector formula crops by $1.28\times$ (ink-derived $M \approx 1.71$), and aligned them into a 3-slot centered row with right-margin equation numbers.

The reader has now evaluated the magnified formula crops and delivered an unambiguous verdict:
> *"公式按照Latex那样弄吧给一段，而不是给图片，不然太难看了"*  
> — *Typeset the formula as text the way LaTeX does, not as an image of one.*

This document governs the introduction of **reconstructed LaTeX formula typesetting** in the reflow reading column.
- **Single Topic Focus:** This contract covers **only** display formulas typeset from reconstructed LaTeX. Figures, tables, captions, paragraph translation, bilingual cache, and reading-order assembly remain strictly out of scope.
- **Production Code Prohibition:** The author of this document writes zero production code. Production implementation belongs solely to the main agent once this contract is frozen.
- **Strict Invariance of DS-DOC-006 / DS-DOC-008:** The paragraph translation pipeline (`app/bilingual/pipeline.py`), translation prompt, stored bilingual reading artifacts (`_cache/bilingual/<content_hash>_<lang>.json`), and bilingual schema version (`BILINGUAL_SCHEMA_VERSION = "1"`) remain **100% frozen and untouched**.

### 0.2 The Hard Fact: Reconstruction vs. Extraction
**There is no LaTeX in a compiled PDF, and there cannot be.** The PDF format stores positioned glyph indices, vector curves, and font subsets. When the document extractor inspects a formula region, it reads scrambled glyph soup. Measured directly from the reader's paper (`2607.00784v1`):
```text
LInfoNCE = −1 / 2B / B / X / i=1 / " / log / exp(zv / i · zt / i/τ) / PB / j=1 exp(...)
LSigLIP  = −1 / B / B / X / i=1 / B / X / j=1 / log σ / tij / ...
¤h(𝑡) = A(𝑡) h(𝑡) + B(𝑡) 𝑥(𝑡),
```
In this raw stream:
1. $\sum$ is extracted as a capital letter `X`, with upper bound `B` and lower bound `i=1` flattened into adjacent slashes.
2. Fraction bars are lost, replaced by arbitrary `/` delimiters.
3. Superscripts and subscripts are collapsed onto neighboring lines.
4. Mathematical italics and special symbols degenerate into replacement glyphs such as `¤`.

Therefore, a rendered formula is **never an extraction**: it is an **AI reconstruction** generated by a language model interpreting the glyph soup in conjunction with surrounding prose context.

Because a model can hallucinate a bound, invert a subscript, or misread a Greek symbol in ways that look mathematically plausible, this acceptance contract enforces three inviolable principles:
1. **Honest Provenance:** The reader is explicitly informed that a formula is an AI reconstruction.
2. **Instant Ground-Truth Verification:** The reader can toggle instantaneously between the reconstructed LaTeX formula and the original high-resolution PDF vector crop.
3. **Graceful Fallback:** When a reconstruction cannot be produced, fails to parse, or is refused by the model, the paper's own pixels (the DS-DOC-009 vector canvas crop) are displayed without disruption.

### 0.3 Architectural Isolation: Independent Artifact & Cache
To prevent any possibility of invalidating existing paragraph translations:
1. **Separate Cache Storage:** Formula reconstructions are persisted to disk under:
   ```text
   <documents_dir>/_cache/formulas/<content_hash>.json
   ```
   This sits beside `_cache/bilingual/` and `_cache/overview/`. It does not modify or re-serialize existing bilingual reading files.
2. **Independent API Routes:**
   - `GET /api/documents/{id}/formulas` (Cache retrieval; costs **0 provider calls**).
   - `POST /api/documents/{id}/formulas` (Formula reconstruction generation; requires explicit user action).
3. **Independent Lifecycle & Invalidation:** Formula reconstruction has its own schema version (`FORMULA_SCHEMA_VERSION = "1"`), pipeline version (`FORMULA_PIPELINE_VERSION = "1.0.0"`), and prompt version (`FORMULA_PROMPT_VERSION = "1.0.0"`). Upgrading or recomputing formulas never invalidates paragraph translations, and vice versa.

## 1. Executive Judgment: Is this task worth doing?

**Yes. Replacing raster/canvas equation crops with crisp LaTeX typesetting resolves the final aesthetic barrier to monograph-grade reading, transforming illegible glyph soup into searchable, copyable, mathematically beautiful text.**

While DS-DOC-009 succeeded in magnifying equation crops and aligning them cleanly, fixed-resolution PDF vector curves remain visual anomalies within a fluid, responsive text column. Mathematical text set via LaTeX matches the optical weight of the surrounding body font, supports crisp scaling at any device pixel ratio, and allows researchers to copy formula markup directly into LaTeX editors, computational notebooks, and research notes.

Because mathematical formulas are language-agnostic, formula reconstruction is computed once per document content hash and shared across all translation targets, maximizing cache reuse while keeping provider costs minimal (1 call for the reader's paper).

### 2.2 Formula Sizing & Typographic Model

Let:
- $W_{\text{col}}$ be the reading measure container width (nominal 680px).
- $W_{\text{num}} = 64\text{px}$ be the slot width reserved for the right-aligned equation number.
- $W_{\text{avail}} = W_{\text{col}} - (2 \times W_{\text{num}}) = 552\text{px}$ be the maximum symmetrical center slot width.
- $S_{\text{katex}}$ be the base font size for mathematical typesetting.

#### Typographic Scale
To maintain visual harmony with 16px (`1.0rem`) Academic Serif body prose:
- KaTeX math is rendered with `displayMode: true`.
- Container font size is set to `1.125rem` (18px), producing uppercase Latin and Greek math glyphs that optically balance with 16px Charter / Georgia text.
- Top and bottom margins are set to `1.75rem` (`28px`), matching the 28px inter-pair paragraph rhythm established in DS-DOC-009.

#### Wide Formula Containment Model (Zero Sideways Scroll)
A typeset LaTeX equation must **never** trigger a horizontal scrollbar on the reflow reading column (`overflow-x: hidden`).
1. **Prompt-Level Multiline Splitting:** The reconstruction prompt instructs the model to format equations exceeding $\sim 50$ characters using KaTeX multiline environments (`\begin{aligned} ... \end{aligned}`), splitting lines before relational operators (`=`, `\approx`, `\le`) or major binary additions.
2. **Optical Scale Clamping:** In CSS/DOM layout:
   $$\text{scale} = \min\left(1.0, \frac{W_{\text{avail}}}{W_{\text{formula\_natural}}}\right)$$
   If an equation naturally exceeds $W_{\text{avail}}$, it is scaled down via CSS `transform: scale(scale)` or container zoom down to a legibility floor of $0.80\times$ (14.4px).
3. Under no circumstances may `overflow-x: auto` be placed on the formula row; horizontal scrolling on formulas is strictly forbidden.

## 3. Architecture & Data Contracts

### 3.1 Backend Data Model (`backend/app/formulas/models.py`)

```python
from __future__ import annotations

from dataclasses import dataclass, field
from typing import Literal

FORMULA_ARTIFACT_KIND = "formula_reconstruction"
FORMULA_SCHEMA_VERSION = "1"
FORMULA_PIPELINE_VERSION = "1.0.0"
FORMULA_PROMPT_VERSION = "1.0.0"

FormulaStatus = Literal["READY", "PARTIAL", "FAILED"]
ItemReconstructionStatus = Literal["reconstructed", "refusal", "failed", "unprocessed"]

@dataclass(frozen=True)
class FormulaItemView:
    """One display formula block and its reconstructed LaTeX representation."""
    block_id: str
    source_anchor_id: str
    page_number: int
    bbox: tuple[float, float, float, float]
    raw_soup: str
    font_size: float | None = None
    status: ItemReconstructionStatus = "unprocessed"
    latex: str = ""
    equation_number: str | None = None
    refusal_reason: str | None = None
    error_reason: str | None = None

    def is_renderable_latex(self) -> bool:
        return self.status == "reconstructed" and bool(self.latex.strip())

@dataclass
class FormulaArtifact:
    """Content-addressed formula reconstruction artifact for one PDF."""
    content_hash: str
    status: FormulaStatus = "FAILED"
    total_formulas: int = 0
    reconstructed_count: int = 0
    refused_count: int = 0
    failed_count: int = 0
    formulas: list[FormulaItemView] = field(default_factory=list)

    # --- Provenance ---
    ir_pipeline_version: str = ""
    artifact_kind: str = FORMULA_ARTIFACT_KIND
    schema_version: str = FORMULA_SCHEMA_VERSION
    pipeline_version: str = FORMULA_PIPELINE_VERSION
    prompt_version: str = FORMULA_PROMPT_VERSION
    provider_model: str = ""
    provider_base_url: str = ""
    created_at: str = ""
    input_tokens: int | None = None
    output_tokens: int | None = None
    notes: list[str] = field(default_factory=list)

    def is_usable(self) -> bool:
        return self.status in ("READY", "PARTIAL") and bool(self.formulas)
```

### 3.2 Backend API Routes (`backend/app/api/formulas.py`)

1. **Retrieve Cached Formula Reconstructions:**
   - **Route:** `GET /api/documents/{document_id}/formulas`
   - **Cost:** Strictly **0 provider calls**.
   - **Behavior:**
     - If cached and compatible: Returns `200 OK` with JSON serialization of `FormulaArtifact`.
     - If no artifact exists: Returns `404 Not Found` with `FORMULA_NOT_FOUND` error envelope containing exact deterministic plan detail:
       ```json
       {
         "detail": "This paper has no reconstructed formulas yet.",
         "code": "FORMULA_NOT_FOUND",
         "plan": {
           "total_formulas": 7,
           "batch_count": 1,
           "character_volume": 1280
         }
       }
       ```

2. **Generate Formula Reconstructions:**
   - **Route:** `POST /api/documents/{document_id}/formulas`
   - **Payload:** `{"profile_id": str, "force": bool = False}`
   - **Cost:** Bounded batch calls ($\le 15$ formulas per call).
   - **Behavior:**
     - If `force == False` and compatible cache exists: Returns cached artifact immediately (0 calls).
     - Gathers formula blocks and adjacent text windows from Document IR.
     - Runs batched LLM prompts with structured JSON output.
     - Performs 1 bounded repair retry on malformed JSON.
     - Atomically writes artifact to disk at `<documents_dir>/_cache/formulas/<content_hash>.json`.
     - Returns `200 OK` with generated `FormulaArtifact`.

## 4. Acceptance Criteria

### 4.1 P0 MUST — Core Contracts, Offline KaTeX, Typography, Fallback, Bundle Limit

- **AC-P0-01 Independent Content-Addressed Formula Artifact & Cache Storage.**  
  Formula reconstructions must be stored as an independent artifact at:  
  `<documents_dir>/_cache/formulas/<content_hash>.json`.  
  The artifact must carry `artifact_kind: "formula_reconstruction"`, its own `schema_version: "1"`, `pipeline_version: "1.0.0"`, and `prompt_version: "1.0.0"`. Generating, upgrading, or deleting formula reconstructions must NOT touch, invalidate, or overwrite the bilingual reading artifact (`_cache/bilingual/<content_hash>_<lang>.json`).  
  *Evidence:* Backend test generating formulas for a document with existing bilingual reading; asserting `_cache/bilingual/` file modified timestamp and bytes remain unchanged.

- **AC-P0-02 Zero Provider Calls on Paper Open and Reopen.**  
  Opening a document, navigating to the reflow reading column, and scrolling through paragraphs and display formulas must cost strictly **0 provider calls**.  
  `GET /api/documents/{document_id}/formulas` must read strictly from local disk cache and never touch an LLM provider endpoint.  
  *Evidence:* `CountingProvider` assertion verifying `provider.total_calls === 0` across document open, initial load, and page reload (`F5`).

- **AC-P0-03 Pre-Execution Cost & Batch Disclosure.**  
  Before formula reconstruction is executed, the user interface must clearly disclose:  
  1. The exact number of display formulas detected in the paper (computed from `len([b for b in ir.blocks if b.layout_class == 'isolate_formula'])`).  
  2. The exact number of provider calls that will be made, computed deterministically as $\lceil \text{count} / 15 \rceil$.  
  A fabricated token estimate must NOT be shown before the run (conforming to DS-DOC-006 AC_CHANGE_REQUEST 2).  
  *Evidence:* Vitest asserting disclosure text in the ungenerated state contains `"7 处公式"` and `"1 次模型请求"` for the reader's paper fixture.

- **AC-P0-04 Bounded Batching & Contextual Prompt Construction.**  
  Formula reconstruction requests must be batched with a maximum limit of **15 formulas** per provider call. Each formula entry in the prompt payload must provide:  
  1. Formula identifier (`source_anchor_id` or `block_id`).  
  2. Scrambled glyph soup (`text`).  
  3. Extracted font size (`font_size`).  
  4. Surrounding textual prose window (nearest text paragraphs within $\pm 800$ characters).  
  For the reader's paper (7 formulas), the pipeline must execute in exactly **1 provider call**. For Mamba-3 (66 formulas), the pipeline must execute in **5 provider calls**.  
  *Evidence:* Backend test asserting batch partition sizes and prompt structure on the reader's paper and Mamba-3 fixtures.

- **AC-P0-05 Structured Refusal & Bounded Malformed Response Repair.**  
  The reconstruction prompt must define a structured JSON schema requiring each formula to report `status: "reconstructed" | "refusal"`.  
  1. If the model determines that glyph soup is unresolvably corrupted, it must output `status: "refusal"` with an explanatory `refusal_reason`.  
  2. If a provider response contains invalid JSON or schema violations, the pipeline must perform at most **1 bounded repair retry**.  
  3. Formulas with `status: "refusal"` or unresolved errors must be saved with their failure reason and must fall back to displaying the original PDF vector crop in the UI.  
  *Evidence:* Backend unit tests simulating (a) clean reconstruction, (b) explicit model refusal, (c) malformed JSON repaired on retry, and (d) unrecoverable failure.

- **AC-P0-06 Strict Pre-Render KaTeX Validation (Nothing Rendered Before Parse).**  
  A reconstructed LaTeX string must NEVER be rendered to DOM before successful mathematical parsing.  
  Every LaTeX string must be validated through `katex.renderToString(latex, { throwOnError: true, displayMode: true })`.  
  If KaTeX throws a `ParseError`:  
  1. The invalid LaTeX markup must NOT be displayed as text.  
  2. The formula item must immediately fall back to the DS-DOC-009 vector canvas crop (`CropCanvas`).  
  3. A subtle unobtrusive indicator must be attached indicating syntax parse failure.  
  *Evidence:* Vitest test feeding syntactically invalid LaTeX (e.g. `\frac{1}{2`) to the formula renderer; asserting `CropCanvas` is rendered instead of broken KaTeX markup.

- **AC-P0-07 Offline-First Self-Hosted KaTeX & Strict Initial Bundle Ceiling ($\le 310.0\text{ kB}$).**  
  KaTeX must be installed as a local, self-hosted dependency in `frontend/package.json` with all WOFF2 fonts bundled locally. Zero external CDN requests or remote `@font-face` downloads are permitted.  
  This criterion **knowingly supersedes DS-DOC-009 AC-P0-12** (which froze 0 new packages). To bound the cost:  
  1. KaTeX and its assets must be isolated into an asynchronous dynamic code-split chunk (`React.lazy()` / dynamic `import("katex")`).  
  2. The initial production bundle chunk (`dist/assets/index-*.js` produced by `npm run build`) must remain $\le 310.0\text{ kB}$ (measured baseline `307.87 kB`, headroom $\ge 2.0\text{ kB}$).  
  *Evidence:* Production bundle audit script asserting `dist/assets/index-*.js` size $\le 310,000$ bytes, and network inspection confirming 0 requests to external CDN domains during formula rendering.

- **AC-P0-08 3-Slot Grid Layout & Horizontal Centering.**  
  Reconstructed display formulas must be rendered within the 3-slot balanced grid established in DS-DOC-009:  
  1. Slot 1 (Left): Fixed balancing spacer ($64\text{px}$).  
  2. Slot 2 (Center): Typeset KaTeX display math, horizontally centered relative to the 680px reading column (left and right margins to column edges equal within $\pm 4\text{px}$).  
  3. Slot 3 (Right): Equation number (e.g. `(1)`), aligned flush to the right margin of the reading column.  
  *Evidence:* Vitest bounding rect measurement asserting center of KaTeX math container matches column midpoint $X \approx W_{\text{col}} / 2$.

- **AC-P0-09 Optical Math Sizing & Vertical Rhythm.**  
  Typeset KaTeX math must harmonize optically with the surrounding 16px (`1.0rem`) Academic Serif body prose:  
  1. KaTeX display math container font size must be set to `1.125rem` ($18\text{px}$ $\pm 1\text{px}$).  
  2. Top and bottom margins on the formula container must enforce `1.75rem` ($28\text{px}$ $\pm 2\text{px}$), maintaining the 28px inter-pair rhythm established in DS-DOC-009 §2.1 D6.  
  *Evidence:* Vitest computed style assertions verifying `fontSize` is between $17\text{px}$ and $19\text{px}$, and `marginTop` / `marginBottom` $\ge 26\text{px}$.

- **AC-P0-10 Strict Horizontal Containment & Optical Auto-Scale (Zero Sideways Scroll).**  
  The reflow reading column must enforce `overflow-x: hidden`. No formula, regardless of length, may cause the reading column to scroll horizontally.  
  1. The prompt must instruct the model to format long equations using `aligned` environments with line breaks (`\\`).  
  2. In DOM layout, if a formula's natural rendered width exceeds the available center slot ($W_{\text{avail}} = W_{\text{col}} - 128\text{px}$), the container must smoothly scale down via CSS optical transform (`transform: scale(...)`), clamped to a floor of $0.80\times$ ($14.4\text{px}$).  
  3. Horizontal scrollbars on formula rows (`overflow-x: auto` / `overflow-x: scroll`) are strictly forbidden.  
  *Evidence:* Browser test in `frontend/scripts/e2e-reflow-bilingual.mjs` loading an ultra-wide equation; asserting `scrollWidth === clientWidth` on the reading container.

- **AC-P0-11 Clear Provenance Tagging & Ground-Truth Flip Affordance.**  
  1. Every typeset reconstructed formula must display a discrete provenance badge: `[AI 重建]` with tooltip:  
     *"此公式由模型根据 PDF 字形还原，可能存在符号或下标偏差。点击可查看原版清晰剪裁。"*  
  2. Clicking anywhere on the formula surface (or pressing `Enter`/`Space` when focused) must flip the item in-place to display the original PDF vector crop (`CropCanvas` at $M \approx 1.71$ magnification) with an amber badge `[原版 PDF 剪裁 · 点击切回 LaTeX]`.  
  3. Clicking again must return the item to typeset KaTeX.  
  *Evidence:* Vitest user-event interaction test asserting click on `reflow-formula-math` swaps DOM to `CropCanvas`, and second click restores KaTeX rendering.

- **AC-P0-12 Geometric Equation Number Association for Unlinked Blocks.**  
  For PDF documents where extractor `caption_of` is null for equation numbers (such as the reader's paper fixture, which has 6 unlinked numbers):  
  The assembly pipeline must associate a formula block with an unlinked `formula_caption` block or numeric block on the same page if their vertical midpoints overlap within $\pm 20\text{ pt}$ ($|y_{\text{mid\_formula}} - y_{\text{mid\_num}}| \le 20\text{ pt}$).  
  The associated number must be extracted and placed into Slot 3 of the formula row.

## 7. Round 1 review and freezing — 2 AC_CHANGE_REQUESTs

Read against the repository and against the papers it holds. **D1–D8 are
accepted**, and three of them are what make this tranche honest rather than
merely attractive: **D2** (the model may refuse, and a refusal shows the paper's
own pixels — the failure mode of this feature is a formula that looks right and
is not, and a refusal is the only defence the pipeline itself can offer), **D6**
(the badge and the one-click flip to the crop, which is the defence the *reader*
has), and **D8** (equation numbers the extractor never associated with their
formulas).

**Two measurements from the real papers, before freezing:**

- **D8's heuristic works where it is claimed.** Measured on the reader's own
  paper: pairing unlinked `formula_caption` blocks to formulas by
  `|Δy_mid| ≤ 20 pt` pairs **6 of the 7 formulas** — exactly the 6 equation
  numbers AC-P0-12's evidence names. On Mamba-3 it pairs 27 of 66, which is
  honest: that paper prints 28 numbers for 66 formulas, so most of its formulas
  have none. AC-P0-12's evidence is scoped to the reader's paper and stays there.
- **`text-3xs` is not a class this project has.** `frontend/tailwind.config.js`
  defines `2xs` (`0.6875rem`) and nothing smaller. The DOM sketches in §2.3 use
  `text-3xs` on the provenance badges, which Tailwind would emit as no class at
  all — a badge at the inherited size, which is not what the sketch shows.

### AC_CHANGE_REQUEST 1 — the optical clamp needs a terminal fallback

**Old wording, AC-P0-10:** the container scales a too-wide formula down to a
floor of `0.80×`, and horizontal scrolling on a formula row is strictly
forbidden.

**New wording:** the same clamp, with what happens when the floor is not enough:
`scale = clamp(avail / natural, 0.80, 1.0)`; if a formula is *still* wider than
its slot at `0.80×`, the item renders the paper's own vector crop instead —
through the same path a refusal takes — with the same badge that says the reader
is looking at the original.

**Reason.** As frozen, the two clauses can contradict each other: an equation
long enough to need a scale below the floor cannot both stay above the floor and
stay inside the column, and the criterion leaves no third option. A hard
`transform: scale()` on an element wider than its container also *paints* outside
the column even when the container does not scroll — the overflow is invisible to
`scrollWidth` and visible to the reader. The escape hatch is already in this
document: D3 and AC-P0-06 both treat "the reconstruction cannot be shown" as
"show the paper". Measured context for the floor's usefulness: the reader's
paper's display formulas are 102–216 pt wide (median 190) — none of the seven
needs any clamp at all inside a 552 px slot; the clamp is for the Mamba-3 kind of
paper, where formulas reach 464 pt.

### AC_CHANGE_REQUEST 2 — the provenance badge uses a size this project defines

**Old wording, §2.3:** the badge and the flipped-state label carry `text-3xs`.

**New wording:** `text-2xs` — the same size the reflow's counts, plan line and
gap notices already use.

**Reason.** Measured: `tailwind.config.js` extends `fontSize` with `2xs` only, so
`text-3xs` resolves to nothing and both badges would render at the inherited
size — larger than the formula they annotate, which is the opposite of
unobtrusive. This is a naming fix, not a design change.
